Exercise 5.1 · vertical bar chart

Which 55-inch screen type uses the most energy?

The first chart answers a simple comparison question. Every bar is one screen technology, and its height is the mean labelled energy consumption of the 55-inch models in the cleaned 2026 registration data. The bars are sorted from highest to lowest so the ranking is immediate.

372

LED has the highest average at 372 kWh/year across 536 models.

362

OLED is close behind at 362 kWh/year across 61 models.

329

LCD is the lowest at 329 kWh/year across 71 models.

How the chart is built

  1. Set the margins and inner chart The SVG has a fixed viewBox. A margin object reserves space for the axes and labels, and a translated group becomes the plotting area.
  2. Make the scales scaleBand divides the x-axis between LED, OLED and LCD. scaleLinear maps energy values to bar heights, starting at zero.
  3. Draw the axes The bottom axis labels the screen technologies. The left axis shows kWh/year, and both axes have a descriptive label.
  4. Bind the bars and labels Each row becomes a group containing a rectangle, a value label and a model count. The value label makes the exact number readable without a tooltip.
js/bar-chart.js · scales and bars 
const xScale = d3.scaleBand()
  .domain(data.map(d => d.screenTech))
  .range([0, innerWidth])
  .padding(0.32);

const yScale = d3.scaleLinear()
  .domain([0, d3.max(data, d => d.avgEnergy) * 1.16])
  .nice()
  .range([innerHeight, 0]);

innerChart.append("g")
  .attr("class", "axis axis-x")
  .attr("transform", `translate(0, ${innerHeight})`)
  .call(d3.axisBottom(xScale).tickFormat(d => d.toUpperCase()));

innerChart.append("g")
  .attr("class", "axis axis-y")
  .call(d3.axisLeft(yScale).ticks(5));

Data preparation · KNIME

Build the 55-inch CSV, step by step.

This is the part to do in KNIME. The repository includes data/tv_2026_cleaned.csv — the Week 4 cleaned 25-brand table — so you can start from the cleaned table and skip the Week 4 brand-cleaning steps. If you want to rebuild the cleaned table from the raw registration file, apply the Week 4 brand filters first, then follow the same steps.

The key trap: screensize is stored in centimetres, not inches. A filter of screensize = 55 returns zero rows. The 55-inch class sits around 138.7–138.8 cm; the median is 138.783 cm. Filtering that range keeps 668 models.

Before you start: open KNIME Analytics Platform, choose File → New → New KNIME Workflow, name it week5_screen_energy and click Finish. The Node Repository is at the bottom-left. Drag each node onto the canvas, connect the output port (right side) to the next node's input port (left side), right-click the node → Configure, then execute it with the green traffic-light button.

Why this range? The data uses panel size in centimetres. 138.783 cm is both the most common exact value in the 55-inch class and the median; 138.798 cm is the next most common. The range keeps all the 55-inch variants without pulling in 50-inch or 58-inch sets.

3

Turn the screen technology into three tidy labels

Add a Rule Engine. Use Screen_Tech as the input column and create a new column called Screen_Type. 

$Screen_Tech$ = "LCD (LED)" => "LED"
$Screen_Tech$ = "OLED" => "OLED"
$Screen_Tech$ = "LCD" => "LCD"
TRUE => "Other"

Execute the node. You should see three screen types. The TRUE line is a safety net: any unexpected value becomes Other instead of breaking the workflow.

Do not use String Replacer for this. Replacing LCD first would turn LCD (LED) into LED (LED). The Rule Engine checks the full value, so the order is safe.

Exercise 5.2 · scatter plot and line chart

How have Australian electricity spot prices changed?

The second chart starts as a scatter plot: one circle for each year, positioned by year on the x-axis and average price on the y-axis. Once the points are in place, a line generator connects them in year order. The result is both a scatter plot and a line chart — the circles show the observations, and the line shows the trend.

$144.5

The 2022 peak is the highest average in the series.

$132.5

The series ends at $132.5/MWh in 2024, still well above the 1990s.

$41.5

In 1998, the average was $41.5/MWh. The long-run direction is up.

From scatter to line

  1. Load and type the data d3.csv reads the file. The row conversion turns Year and Average Price (notTas-Snowy) into numbers.
  2. Find the domains d3.extent gives the first and last year. A linear scale maps that range to the width of the chart; a second linear scale maps price to height.
  3. Draw the scatter plot Each row becomes a circle. The circle's cx is the scaled year and its cy is the scaled price.
  4. Connect the points d3.line uses the same x and y accessors. The path is drawn with fill: none so only the stroke is visible.
  5. Label the axes The x-axis uses d3.format("d") so years are integers, not decimals. The y-axis is labelled “Average price ($/MWh)”.
js/line-chart.js · extent, scales and line 
const xScale = d3.scaleLinear()
  .domain(d3.extent(data, d => d.year))
  .range([0, innerWidth]);

const yScale = d3.scaleLinear()
  .domain([0, d3.max(data, d => d.averagePrice) * 1.12])
  .nice()
  .range([innerHeight, 0]);

const lineGenerator = d3.line()
  .x(d => xScale(d.year))
  .y(d => yScale(d.averagePrice))
  .curve(d3.curveMonotoneX);

innerChart.append("path")
  .datum(data)
  .attr("class", "line-path")
  .attr("d", lineGenerator);

Exercise 5.3 · donut chart

What mix of TV sizes does the 2026 market sell?

A donut is a part-to-whole chart: every slice is a share of the same total. This chart groups the 4,240 registered models into three screen-size bands, so the market mix is visible at a glance. The categories are prepared in KNIME; D3 only draws the three-row summary.

Small is up to 42.5 inches, medium is 42.5–65 inches, and large is over 65 inches. The 42.5-inch boundary keeps the 43-inch class in the small group; the 65-inch boundary keeps the 65-inch class in the medium group. The KNIME rules below show the exact logic.

51.7%

Medium is the largest group: 2,193 models between 42.5 and 65 inches.

31.3%

Large models over 65 inches account for 1,326 registrations.

17.0%

Small models up to 42.5 inches make up 721 registrations.

How the donut is built

  1. Load the KNIME summary d3.csv reads the three rows. The Count column is converted to a number, while the row order stays large, medium, small.
  2. Make a colour scale d3.scaleOrdinal maps the three categories to d3.schemeSet2. This is the ordinal equivalent of the band scale used for the screen types in 5.1.
  3. Turn counts into angles d3.pie() calculates each slice's start and end angle. .sort(null) keeps the CSV order instead of re-sorting by value.
  4. Draw the arcs d3.arc() turns the angles into SVG paths. An innerRadius of 60% of the outer radius cuts out the centre and leaves room for the total.
  5. Label the slices arc.centroid(d) gives the middle of each slice, so the category name and share can be placed inside the ring.
js/donut-chart.js · ordinal colour, pie and arc 
const color = d3.scaleOrdinal()
  .domain(data.map(d => d.Screensize_Category))
  .range(d3.schemeSet2);

const pie = d3.pie()
  .value(d => d.Count)
  .sort(null);

const arcGenerator = d3.arc()
  .innerRadius(radius * 0.6)
  .outerRadius(radius);

innerChart.selectAll("path")
  .data(pie(data))
  .join("path")
  .attr("d", arcGenerator)
  .attr("fill", d => color(d.data.Screensize_Category));

innerChart.selectAll("text")
  .data(pie(data))
  .join("text")
  .attr("transform", d => `translate(${arcGenerator.centroid(d)})`)
  .text(d => d.data.Screensize_Category);

Exercise 5.3 · data preparation

Build the size summary in KNIME.

The donut reads a three-row CSV. This workflow adds an inch column, classifies each model, counts the rows and writes the file. It is shorter than the 5.1 recipe because there is no mean to calculate.

Stage 1 CSV Reader Read the cleaned TV table.
→
Stage 2 Math Formula Create screensize_inch.
→
Stage 3 Rule Engine Small, medium, large.
→
Stage 4 GroupBy Count models per group.
→
Stage 5 CSV Writer Write the chart-ready CSV.
1

Read the cleaned TV table

Add a CSV Reader and point it at data/tv_2026_cleaned.csv. Use a comma delimiter, the first row as the header and UTF-8 encoding.

Execute it and confirm 4,240 rows × 33 columns.

2

Create a screen-size column in inches

The cleaned table stores screensize in centimetres. Add a Math Formula node and create screensize_inch: 

$screensize$ / 2.54

Why convert? The exercise defines the categories in inches. One inch is 2.54 cm. If your raw file already has a screensize_inch column, skip this node and use that column in step 3.

3

Classify each model

Add a Rule Engine and create Screensize_Category. The exercise screenshot calls this step “Expression”; the Rule Engine is the easier KNIME 5.x equivalent. 

$screensize_inch$ <= 42.5 => "small"
$screensize_inch$ <= 65 => "medium"
TRUE => "large"

Rules are checked from top to bottom. A 42.5-inch model becomes small; a 43-inch model becomes medium; anything over 65 inches becomes large.

4

Count the models in each group

Add a GroupBy node.

Group column
Screensize_Category
Aggregation
Submit_ID → Count; output name Count

Execute it. GroupBy sorts the keys alphabetically, so the output is large, medium, small — exactly the order the donut uses.

5

Write the chart-ready CSV

Add a Column Filter and keep only Screensize_Category and Count. If GroupBy named the count column Count(Submit_ID), use a Column Renamer to call it Count. Then add a CSV Writer.
