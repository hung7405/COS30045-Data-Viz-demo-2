Exercises 6.1–6.2 · Histogram and filters

How much energy does a television use?

A histogram groups a continuous variable into bins and shows how many observations fall into each one. This chart uses the labelled energy consumption of 4,233 TV models from the January 2026 registration data. Use the buttons to compare LED, LCD and OLED TVs, or the optional screen-size filters. The scatterplot below shows the same models by star rating.

About the long tail: one model uses 2,652 kWh/year. It sits in the final 2,600–2,800 bin, which is why that bar is almost invisible. The chart keeps it so the distribution is honest; the main story is still the concentration between 0 and 1,000 kWh/year.

Exercise 6.3 · Scatterplot

Energy consumption by star rating

The scatterplot plots star rating on the x-axis and labelled energy consumption on the y-axis. Each point is one TV model, and colour identifies LED, LCD or OLED. Dense vertical clusters appear at the half-star and whole-star ratings; the colour coding is useful for comparing the groups but is hard to read in the densest parts of the cloud.

How it is built: js/scatterplot.js uses the shared xScaleS, yScaleS, colorScale and innerChartS. The x-domain starts at 0 and ends at the maximum star rating; the y-domain starts at 0 and ends at the maximum energy value. Circles use opacity 0.5 and no stroke so overlapping models remain visible. The legend is drawn inside the SVG in the top-right corner.

Try it: hover any circle. The circle grows and a tooltip appears with the screen size, the energy consumption, the star rating and the brand — that is Exercise 6.4, explained in the next section.

Exercise 6.4 · custom tooltip

Reading a single model out of the cloud

The scatterplot is dense: hundreds of models share the same star rating, so the position alone cannot tell you which TV a circle is. The tooltip fixes that. Hovering a circle shows screen size, energy consumption, star rating and brand for that exact model.

Why an SVG group instead of an HTML div

The usual approach is an absolutely positioned <div>. Here the tooltip is an SVG <g> appended to innerChartS, the same group the circles live in. That means it inherits the chart's coordinate system: it scales with the viewBox, stays aligned when the window resizes, and never drifts on a mobile screen where the SVG is scaled down. The two size constants (tooltipWidth, tooltipHeight) were already declared in shared-constants.js for this step.

js/interactions.js · createTooltip() 
const tooltip = innerChartS
  .append("g")
  .attr("id", "scatter-tooltip")
  .attr("pointer-events", "none")  // never blocks the circles
  .attr("opacity", 0);          // hidden until hover

tooltip.append("rect")
  .attr("rx", 6)
  .attr("width", tooltipWidth)
  .attr("height", tooltipHeight);

The three steps that make it work

Step 1 createTooltip() Build the hidden group once.
→
Step 2 handleMouseEvents() Attach the three listeners.
→
Step 3 positionTooltip() Follow the pointer, stay inside.
1

Attach three listeners to every circle

handleMouseEvents() selects circle.scatter-circle inside innerChartS and attaches mouseover, mousemove and mouseout with D3's .on().

js/interactions.js · handleMouseEvents() 
innerChartS
  .selectAll("circle.scatter-circle")
  .on("mouseover", function (event, d) {
    d3.select(this).raise().attr("r", 5).attr("opacity", 1);
    writeTooltipContent(d);
    positionTooltip(event);
    tooltip.raise().attr("opacity", 1);
  })
  .on("mousemove", event => positionTooltip(event))
  .on("mouseout", function () {
    d3.select(this).attr("r", 3).attr("opacity", 0.5);
    tooltip.attr("opacity", 0);
  });

raise() moves the hovered circle to the top of the group so its outline is not hidden by neighbours. The tooltip is raised again afterwards, otherwise the circle would paint over it.

2

Write the values and size the box to the text

The tooltip has three short lines. The first one carries the value the exercise asks for — the screen size — together with the screen type:

js/interactions.js · writeTooltipContent() 
tooltip.select(".tooltip-headline").text(`${d.screenSize}″ ${d.screenTech}`);
tooltip.select(".tooltip-detail").text(`${d3.format(",")(d.energyConsumption)} kWh/year`);
tooltip.select(".tooltip-context").text(`${d.star}★ · ${d.brand}`);

// measure the real text, so long brand names are not clipped
let textWidth = 0;
tooltip.selectAll("text").each(function () {
  textWidth = Math.max(textWidth, this.getBBox().width);
});
tooltip.select("rect").attr("width", Math.max(tooltipWidth, textWidth + 20));

getBBox() returns the rendered size of the text in user units. Using it instead of a fixed width means a long brand name widens the box instead of spilling outside it.

3

Keep the tooltip on the canvas

d3.pointer(event, innerChartS.node()) converts the mouse position into the chart's own coordinates, so the tooltip follows the pointer correctly at any window size. Two flips keep it visible near the edges:

js/interactions.js · positionTooltip() 
let x = pointerX + 12;
let y = pointerY - boxHeight - 12;

if (x + boxWidth > innerWidth) x = pointerX - boxWidth - 12; // flip left
if (y < 0) y = pointerY + 14;                    // flip below

 tooltip.attr("transform", `translate(${x}, ${y})`);

Because the groups are translated rather than redrawn, moving the mouse only updates one attribute. The tooltip stays cheap even with 4,233 circles on the page.

One more thing that is easy to miss: resizing the window redraws the scatterplot, which deletes every circle. The resize handler in js/scatterplot.js therefore calls createTooltip() and handleMouseEvents() again after the redraw; without that the tooltip silently stops working after a resize.

Build notes

How the histogram is built

  1. Load the data. js/load-data.js reads data/Ex6_TVdata_withStar.csv with d3.csv() and converts screenSize, star and energyConsumption to numbers. The loaded rows and the 14 bins are printed in the browser console.
  2. Share the constants. js/shared-constants.js holds the chart dimensions, colours, the histogram and scatterplot scales, the bin generator and the filter arrays. Keeping the generator here means Exercise 6.2 can reuse it when the filters change the data.
  3. Create the bins. The generator uses d3.bin().value(d => d.energyConsumption).domain([0, 2800]).thresholds(14). Each bin has an x0 lower bound, an x1 upper bound and a length count.
  4. Scale the axes. xScale maps kWh/year to horizontal position; yScale maps the bin count to vertical position. The x domain uses the first bin's x0 and the last bin's x1; the y domain runs from zero to the tallest bin.
  5. Draw the bars. Each <rect> starts at xScale(d.x0), has a width of xScale(d.x1) - xScale(d.x0) and a height of innerHeight - yScale(d.length). The small gap lets the card show through between bars.
  6. Add the axes and labels. d3.axisBottom() and d3.axisLeft() draw the ticks. The axis labels name the variable and the count, so the chart can be read without the surrounding page.
  7. Filter the histogram. js/interactions.js builds the buttons from filters_screen and filters_size, updates the active state, filters the rows and re-bins them with the shared binGenerator. The bars transition to their new heights while the x-axis stays fixed for comparison.
js/shared-constants.js · bins and filters 
const binGenerator = d3.bin()
  .value(d => d.energyConsumption)
  .domain([0, 2800])
  .thresholds(14);
Data preparation · KNIME

Build the six-column CSV in KNIME.

The page charts data/Ex6_TVdata_withStar.csv, and that file comes out of the Week 6 KNIME workflow. The supplied workflow (W6_TVdata.knwf) already contains the chain below plus six Histogram nodes and a Scatter Plot node for exploring the data before you draw it in D3.

Stage 1 CSV Reader Raw January 2026 export.
→
Stage 2 Duplicate Row Filter One row per model number.
→
Stage 3 Row Filter Available + sold in Australia.
→
Stage 4 Expression / Math Formula Tidy brand, screen size in inches.
→
Stage 5 Column Renamer Six lower-case names.
→
Stage 6 CSV Writer Write the chart-ready CSV.
1

Read the raw export

Add a CSV Reader for tv_2026_02_15.csv: comma delimiter, first row as header, UTF-8. The export has 4,724 rows × 32 columns.

2

Remove the duplicate model numbers

Add a Duplicate Row Filter on Model_No, keeping the first occurrence. A family can be re-registered under the same model number, and two identical circles on top of each other are invisible in a scatterplot.

This node comes before the row filter. Removing duplicates first and then filtering is not the same as filtering first and then removing duplicates — the second order keeps a duplicate that only appears in the filtered subset.

3

Keep available models sold in Australia

Add a Row Filter with two conditions joined by AND.

Condition 1
Availability Status = Available
Condition 2
SoldIn matches wildcard Australia*

The wildcard is what makes this work: SoldIn holds multi-value strings such as Australia,Fiji,New Zealand, so an exact match on Australia would drop most of the market.

4

Convert centimetres to inches and tidy the brand

Add a Math Formula node that replaces the screensize column with whole inches: 

round($screensize$ / 2.54)

Then add an Expression node (or a String Cleaner) that replaces Brand_Reg with its lower-case form: 

lower_case($["Brand_Reg"])

Also add a String Replacer for the one inconsistent label: LCD (LED) → LED in the Screen_Tech column. The page groups by three screen technologies, so the combined label has to collapse into one of them.

5

Rename to the six names the page reads

Add a Column Renamer with these mappings.

Brand_Reg
brand
Model_No
model
screensize
screenSize
Screen_Tech
screenTech
Star2
star
Labelled energy consumption (kWh/year)
energyConsumption

Then add a Column Filter that keeps only those six columns. The names are case sensitive in the JavaScript: screenSize is not screensize.

Check your work

What to demonstrate

  • All 14 histogram bars use the same x positions before and after filtering.
  • LED, LCD and OLED each update the bar heights and the status line.
  • The optional size filters combine with the screen-type filter.
  • The scatterplot has 4,233 circles, three legend colours and labelled axes.
  • Hovering a circle grows it and shows screen size, energy, star and brand.
  • The tooltip flips left or below near the edge and never leaves the chart.
  • The tooltip still works after the window is resized.
  • The page stays readable at desktop and mobile widths.
